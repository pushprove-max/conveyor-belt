# 1.0.0

The first public release of Conveyor, a Claude Code plugin that turns GitHub issues into reviewed, tested commits on your default branch.

## Cards

- Each open issue becomes a card. Conveyor builds it in a fresh git worktree, a second model reviews it, a fix session fixes what the review finds, and the card's tests run.
- A card that passes lands as one commit on your default branch.
- A card that needs a person waits for you with its work kept. The other cards go on.
- You set how many cards run at once, and which model builds, reviews and judges.
- Cards run in Claude Code, Codex or OpenCode.
- An issue can wait on other issues. Its card waits until they are done.
- Cards that are ready at the same time land together in one batch, tested once. When the batch fails, Conveyor splits it to find the card that breaks it, and the other cards land.
- A card whose change still applies to a newer main lands on the tests it already passed.

## Review

- A second model reviews each card, at most three times. Each finding has a level from P0 to P3.
- A review after a fix checks that the fix holds, and raises a declined finding again only with a new reason.
- The judge, when you turn it on, reads each review and declines the findings that do not earn their place.
- Findings still open after the last review become follow-up issues, which become cards of their own.
- Each declined finding shows on the Board with who declined it and why. You can file one as an issue.
- A project can list what it knowingly lives with in its README, and the reviewer does not raise it.

## Tests

- When a card's tests fail, only the failed tests run again before any fix. A card whose second run passes goes on.
- After a fix, the card runs only the tests that failed and the tests of the files the fix changed.
- A test that fails and then passes goes on the flaky-test record. A test that is flaky again and again gets an issue, and card test runs keep it off until that issue closes.
- Conveyor measures the CPU time of each test file. Each file has a budget, and the project has one. A card with slow test files still lands and shows them in a note.
- The Tests page lists every test file of the project, with its CPU time, its last runs and its status. You can sort by any column and search by file name.
- On the Tests page, a model can judge a test or explain a slowdown, and the test rules can file an issue for a slow or flaky file.

## Push

- Push landed runs the project's full test suite on main first, and pushes the landed cards only when it passes. When it fails, each failed test runs alone: a flaky test goes on the record, and a real failure becomes a fix card.
- Push now pushes the landed cards at once, with only the project's own pre-push checks.
- The Push when a card lands rule pushes each card on its own after it lands. It is off in a new install.
- A push that fails its checks shows on Needs you. A push that fails for the network tries again on its own.

## Releases

- The Board's Release panel takes a release through three steps: the release notes, the full test suite, and the release.
- Draft notes has a model write the notes for you to read and change.
- A release uses a suite run that passed on the same main, and does not run the whole suite again. After a change, it runs again only the test files that failed or changed.
- Only you start a release, with a second click.

## The Board

- A local web page shows the belt for each project on the machine.
- The Overview tab has the panels Needs you, On the belt, Queue, Landed today, Release, Declined, Health, Lanes, Cost and Metrics.
- Needs you has Retry and Close for each blocked card, and Queue for each change that waits for your yes.
- Health shows the flaky tests, the tests kept off card runs, and each error in a short sentence.
- The Control tab pauses or stops the loop, shows the weekly limit and today's cost, and has Push landed, Push now and Run full test suite.
- The Rules tab holds the settings, including the price of each model, which you can add to or change, and the issues held by you or by a label.
- Each card's steps show the review findings with their proof, why each fix started, and how many tests ran.
- Belt 3D shows the belt as a conveyor line, with each card on the step it is in.

## Lanes

- The Fast lane is your own worktree for a change made by hand. It lands as one card, reviewed and tested as any card is.
- The Research lane is a read-only worktree in a sandbox with no network. The issues it files stay held until you release them.

## In Claude Code

- `/units` shows the belt beside your chat, above the prompt and in the status line.
- The Foreman, a Claude Code session in your project's checkout, brings you blocked cards and changes that wait for your yes, and asks you by a picker.
- The Foreman wakes when a card it waits for lands, when a card is blocked, and when a suite run ends. Its status command shows the belt, the held issues, the run in progress and what needs you.
- While you are away, the Foreman can work by your away rules, or decide your open questions by the way you decided before.
- Commands that come with the plugin pick a planning skill for a task and run review rounds on a change.

## Setup

- `/conveyor-belt:setup` asks a few questions, saves the settings, installs the Board and can start Conveyor as this machine's service.
- A new project follows releases: it runs the newest released version. You can set the pack's `plugin` to follow `main` or to pin one commit instead.
