# 1.12.0

This release sorts review findings by the harm they do, lets no review finding block a card, and makes a card's Test step faster.

## Review findings

- The judge gives each review finding a kind, by what its failure does. The kinds are harm, self-heals, cleanup, already guarded and docs drift.
- A review finding never blocks a card. The card lands, and each finding that is still open becomes a follow-up.
- A privacy hit in a card's own change never lands. The card gets up to 3 fix sessions, each with one more review. When the last review still finds the hit, Conveyor shuts the card and keeps its work.
- A harm finding of level P1 at the last review gets one more fix session and one more review before the card lands. A card gets this fix only once. It gets none when the review also finds a P0 harm finding, a repeated finding of level P0 or P1, or a privacy hit, or when the card is a retry that lands its kept work on its kept review.
- A harm finding outside the card's change becomes a follow-up card at once. The judge no longer drops a real defect that the card did not cause.
- A finding of another kind goes to the self-heals list, or to the docs list for docs drift. One batch card fixes all the entries of an area.
- An entry of the self-heals list that nobody fixed or saw again in 30 days leaves the list. Conveyor keeps it in a record of dropped entries.
- From the second review on, a new P2 harm finding in the fix becomes a follow-up card. It does not start another fix round.
- The judge counts a weak test as a defect.
- A new setting on the Rules tab names the levels at which the judge can decline a finding as a rare case.
- When ast-grep is installed, a Claude review can run a read-only ast-grep search, and build and fix sessions use it.
- When a card with a GitHub issue blocks after a review, its comment on the issue quotes the findings that caused the block. A list shows the other findings of that review. When the block reason holds only the start of a long finding, that finding goes in the list and is not quoted. When the comment has no more room, the list gives the number of findings it leaves out, and the kept review holds them.

## Tests

- A card's Test step stops at its first failed case. A card that fixes a red main does not stop at its first failed case, but it still skips the flaky cases and the files that passed before with the same inputs. Set the rule "Stop a card's tests at the first failure" to Off to run every case. A release still runs every case.
- A card runs its selected test files side by side on the free test slots.
- A card gets 3 fix rounds for failing tests before it blocks.
- When a test file reports the files that it reads, Conveyor chooses a card's tests from them. It uses an earlier pass again when those files did not change.
- A card does not start its Test step while main is red.
- The new rule "Only the Test step runs tests" is off by default. With it on, a card session runs no test command.
- The new rule "Push after a combined test run" is off by default. With it on, Conveyor pushes landed cards together after one test run on main passes.
- When the project's pre-push hook supports it, Conveyor runs the push checks of a card's change before the landing. A failure blocks the card.
- A push blocked by a check that cannot pass on a retry gets a fix card. Conveyor picks that card ahead of the queue.
- A new group of rules, "Cards with no GitHub issue", has a switch for each kind of card. A kind that is on starts its cards with no issue.
- The setting "Test history starts at" sets the date from which the Tests page and the judge read test results.
- A test run that cannot start for lack of temp space no longer marks main red.
- The privacy check no longer counts a private network address or a ruling ID as a hit.

## Start

- The loop starts no new card when the free disk space for cards is under 3 GB. The pack's `tunables.minFreeDiskGb` changes the limit.
- The card cap counts every card on the belt, except a card that lands or pushes.
- The machine service no longer ends by itself after the loop restarts on new code.
- Conveyor flags an issue that waits on a dependency that nothing will build.
- Auto no longer retries a blocked card again and again when each retry blocks for the same reason.
- When main has no notes for a release, Conveyor lands the notes draft as a card. Then it runs the suite.

## Large work: a parent issue and its parts

- A later card of the same issue no longer files its left-out part again.
- A part that another card landed now closes its parent. A parent whose parts are all done closes again.

## The Board

- The new Self-heals page shows tiles, area cards, the list of entries, a detail panel and a Docs section. A click on a tile filters the entries.
- On the Self-heals page, you can file a batch card or a docs sweep for an area or for the entries you select. You can also move an entry up to harm or drop it.
- The Rules tab shows and sets the number of days after which a self-heals entry expires.
- A dollar amount that holds an estimated step has an estimate mark, for example ~$4.12. Conveyor also records the tokens of a review that timed out.
- A card's Lint step shows one row for each command, with a result chip. Its Review step shows one list of findings.
- With Show set to All projects, the Control, Rules, Tests and Benchmarks tabs let you choose a project.
- Needs you no longer lists an issue whose retried card is building.

## /units

- /units gets its data faster.
- /units names a card with no issue by its kind and its parent, and its Title shows the finding.
- BUILD MATRIX no longer shows a waiting card as running.

## Foreman

- The Foreman cannot end a reply while a blocked card is not reported to you.
- The Foreman no longer puts cards that you queued from the Board back on hold. Your holds no longer disappear when the Foreman edits an issue.
- The Foreman no longer files an issue twice when the filing is slow.
- The research and fast lanes can send a message to the Foreman.
- The Foreman no longer gets a "GitHub not reached" wake while GitHub answers.
