# 1.11.0

This release makes cards land faster and fail less: ready cards are tested together, a failed Claude build session is resumed, and the build session checks its own work before it ends.

## Cards

- The build session can run one command that runs the project checks, the trailer rule and the Done-when form, and it is told to run it before it ends. The engine still checks after the session.
- The build brief lists the callers of what the issue changes and the test files tied to them, as a starting point.
- A Claude build session that fails for a passing reason, such as an API error or a stall, is resumed once by its session ID when its output names one, and else started again from nothing. A Codex or OpenCode build session starts again in a new session.
- Each build failure has a named class in the card record and the metrics.
- A P1 that the last review finds gets one short fix and a fix-only review. If the P1 still holds, the card blocks with its work kept. It no longer lands with a follow-up.
- A test fix round gets the failing cases first, each with its file and line. A second fix round on the same card runs one effort level higher, within the pack's limits.
- Split is on by default for new projects. A project that set Split keeps its own value.

## Tests and landing

- Ready cards land as a batch that is tested once on the batch's last commit. The cards can change different files. A batch holds up to the pack's `landBatch` cards, and `landBatch` 1 turns batches off. When main moved onto a test file that a card of the batch touches too, the batch runs that file again on main before it lands, once for each change of that card. When the batch fails, Conveyor splits it to find the card that broke it.
- A filter that runs no case is reported as no result, not as a pass.
- An earlier pass is no longer used for a change that only re-indents code.

## Main red

- A fix card for a red main first runs its failing cases on main. When they all pass there, the card closes with no build session.
- At a red commit, cards that wait on the same test file can share one run of it. A card uses an earlier run of a test file at that commit only when the file ended in time in that run, the installed dependencies are the same, and each control test (the pack's `test.control`) that the card needs ran and passed in that run. Else the card runs that test file at that commit itself. A test file that main deleted does not run. A waiting card wakes only when main's state changes.
- The landing that turned main red is recorded.

## Picking and capacity

- The card cap counts build sessions only. A card in review or in its Test step no longer counts against it.
- Among issues of the same order and priority, Conveyor first picks the one that other waiting issues depend on.
- Conveyor records why a card waits, with the time for each cause, and the Board's metrics show it.

## Fixes

- A Claude build session that the API refused can be resumed when it has a session ID.
- A resumed build no longer counts the first build's tokens twice.
