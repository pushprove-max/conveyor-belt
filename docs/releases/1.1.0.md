# 1.1.0

This release makes the test suite faster and easier to read, adds a Foreman status indicator to `/units`, and makes setup ask about lanes and project instruction files.

## Setup

- Setup asks whether to make a fast lane (your own worktree for changes made by hand) and a research lane (a read-only sandboxed worktree).
- Setup checks that your project has the instruction files Claude Code and Codex read, and offers to write optimized ones when they are missing. It never overwrites a file that is already there.
- `doctor` reports the same checks.
- A plugin installed from the marketplace can now read its releases.
- Commands run through the plugin's shim now act on your project's checkout, not the plugin's install folder.

## The Foreman

- The Foreman keeps its role after `/clear`, as it does after a continue or resume. Turning it off before a clear keeps it off.
- `/units` shows whether the Foreman is listening, or says why it is not: not the Foreman session, no waiter running, waiter on an old install, or a watcher down.
- The Foreman's details in `/units` show which session holds the role, the waiter's process and install commit, and each watcher's state.

## Cards

- A card that was blocked for your visible-change approval restarts by itself once the approval line is added to its issue.
- A retried card no longer lands its kept work without a review when the issue has changed.
- `retry <issue> --fresh` drops an issue's kept work, so its next card builds from nothing. The dropped work is kept in a dated folder.
- Failed cases in the full test suite are no longer missed when a retry runs them.

## Tests

- Push landed and the full test suite reuse passing results for files that have not changed since the last whole-suite run on the same commit.
- A passing release check lets Push landed skip running the tests again on the same commit, and the reverse.
- The Board says when a result is reused and how many files reran.
- A test that proves nothing on main no longer blocks a speed-up card. Speed-up cards now prove themselves by a lower CPU time.
- The nightly whole test reports a run as not green when it ran far fewer cases than usual.
- The whole test on main can run once a day at a set time, and it judges failing cases the same way the nightly did.
- Stale entries in the flaky-test record are dropped when their test case no longer exists.

## The Board

- The 3D View tab sits next to Overview and is named "3D View".
- The Tests page is laid out more clearly, with a Settings section that starts collapsed.
- Pick many test files at once and act on them with one bar: Judge, Optimize, Run, or Mutation check.
- Each test file row has Judge, Optimize and Run buttons, and a More menu for the rest.
- Files that have never been timed sort last and say "Not timed yet".
- A file with an issue links to it.
- Judge results are formatted text, with a verdict line first. A verdict to speed up, split, merge or delete can lead straight to Optimize.
- Recent actions lists judge, optimize and other test actions, with their state.
- Optimize shows each file's history: when it was filed, its state, and the CPU time before and after.
- A new Caught column shows how often each test file has caught a real bug. A file with many runs and no catches is marked "Never caught anything".
- Test edits by cards are listed, so you can see when a card weakened a test. A "Weakened" filter shows only those.
- Hollow tests are flagged with a Hollow filter and listed in each file's row.
- Mutation check results show how many mutants each file caught, and list the survivors.
- Tests that run other test files whole are not held to a CPU budget and are never flagged as slow.
- The Tests page can run at most 3 test actions at once; others wait in line.
- Column headers have short hints when you hover or focus them.
