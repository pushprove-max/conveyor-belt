# 1.9.0

This release rebuilds the Board's Benchmarks tab as seven pages, checks the engine's own Python and shell files with lint, and fixes how the Foreman carries over, starts and is woken.

## The Board

- The Benchmarks tab is rebuilt as seven pages: Scoreboard, Versions, Compare, Live run, Task, Task map and Plan a run.
- Benchmark Compare offers each earlier version of a Conveyor arm that has graded results from runs that have ended and are not archived.
- Compare's verdict names the winner's own cost and time, and gives the right task count for a small gap.
- Live run shows the usage guard's share of the week left, and Plan shows whether the run fits in the week left before the guard stops it.
- The Task page shows a task's image size when a run kept it.
- On a phone, the Board's tab bar scrolls sideways to show the tabs that do not fit, and the page stays the width of the screen.
- A card shows its builder, reviewer and judge on separate rows, with the Judge's reason in a callout.
- A card's step shows its effort beside its model, for example "claude-opus-5-5 at high".
- A card whose builder the Judge chose shows that builder, and no longer says the card does not run on it.
- The Tests tab has its own Test settings panel, with clearer rows and labels.
- An umbrella issue that was split shows its slices and their state, and has no Queue button.
- Needs you shows an accurate title for a card that was picked and blocked after the snapshot was taken.
- Plugin problems lists missing model prices, and Conveyor no longer files price issues in your project's repository.
- A card in a review-gate or landing-gate lint fix is labelled once, with the right fix number.
- The Board's Benchmarks page lists no Aider or OpenHands arms.
- The Board, the engine and the Foreman share each Claude account's rate-limit wait. While Claude refuses reads for an account, none of them asks again. When no wait applies, the Board still fetches fresh usage from Claude.

## Cards

- A card whose last review finds a P0 is blocked, not landed with a follow-up.
- A card whose work was done outside the repository, such as filing issues, can close its issue after a review confirms it.
- Builders can no longer schedule or message other sessions, and card sessions no longer keep auto memory.
- A card with a lint command whose script is on main no longer blocks cards that were made before it.
- A card that shares test files waits its turn to land, and skips lint when main changed none of its files, none of the files a lint command reads for all changes, and did not change the pack's `lint` field.

## Tests and Lint

- The engine's Python files are checked with ruff, and its shell files with shellcheck.
- Shell functions and files are checked for length, with an exempt list for those already over the limit.
- Setup asks for your project's own lint command, and offers ready linter entries.
- When the pre-push check fails, Conveyor runs each test file it names again alone, once, and stops the push only if a file fails that run too. The push also stays blocked when the hook names no test file, or fails for a check that is not a test file.
- The engine's own tests run faster and are steadier, with no change that you can see.
- A parallel release suite runs two test files at once by default, and you can change that on the Rules tab.
- A failed test with no message of its own shows the line that failed.

## Releases

- A release holds landing on main until it ends, so cards that finish during it do not move main under the suite.
- For releases after the first, release notes check each line against a real issue or commit before they are written.
- A second release run no longer queues behind the first.

## The Foreman

- The Foreman's role carries over after `/clear`.
- The Foreman's start text fits in Claude Code's hook limit, and its rules arrive in their own hook.
- The Foreman's start is much quicker, reading the live summary from the snapshot.
- The Foreman's role and waiter show within a second in /units.
- A started or resumed Foreman session gets its waiter at once, so it can be woken.
- Auto keeps deciding on the build machine while your Mac is off or the Foreman session is not running.
- Blocked cards with kept work appear as open decisions, and a held main-red issue does too.
- `foreman status` reports the Foreman's own waiter and watcher, and says when its snapshot is behind.
- The Foreman's stop hook and wakes no longer name cards that were already retried.
- The Foreman's saved-state cap counts only open lines, and done items that end with "- DONE" are archived.
- Replies to a wake can include the "Done without asking" line.
- A timed-out Foreman question no longer leaves the engine stopped.

## Units and Pushes

- `/units` and the Board show a push's live progress, elapsed time and result, and say when a push leaves main ahead.
