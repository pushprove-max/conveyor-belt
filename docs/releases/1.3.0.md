# 1.3.0

This release makes setup, the Board and test runs fit more kinds of projects: API keys and other model names, any test naming convention, and projects whose dependencies were missing in card worktrees.

## Setup

- Setup now offers direct API keys for Claude and Codex, not only the subscription login and local proxies.
- Each route offered is checked with one real call first, and a route that fails is shown with the reason instead.
- A fallback route can be set for any role, such as subscription first and an API key second.
- API keys can be kept in Claude Code's settings or in a key file readable only by you, so card sessions run by the background service can use them.
- Setup finds the dependency folders your project needs, such as `node_modules`, and keeps them available in each card's workspace.
- Setup detects your project's test file naming and asks you to confirm it.
- Setup restarts a Board that is running an older version than the project.

## The Board

- Model prices are grouped by provider and family, with models in use shown first and older models folded away.
- A search box finds models by name or alias.
- Prices are edited in place on each model's row, and a changed price can be reset to the built-in value.
- You can add a model the price table does not know.
- You can give a model other names, so sessions using a different model ID are priced and shown under the model's name.
- Model IDs seen in sessions but not priced are listed at the top, with one click to match them to a model or add them as a new model.
- Health no longer warns about subscription usage limits for roles that run on an API route.
- Test times are read from each test runner's own report, so most projects now get them without changing their test command.
- The page header no longer covers the section you are scrolling through.
- A card's test step shows whether it ran only the changed tests or the whole suite, and how many files ran.
- A card that fixes a failing main branch shows its own name instead of a blank issue number.

## Keeping the Board current

- The Board and its live feed reconnect correctly after a host setting changes.
- `/units` shows cards and costs on a one-machine setup.
- Usage and account warnings no longer appear for roles on an API route.

## Sign-in problems

- A failed sign-in pauses the loop at the first failed card and says what to run to fix it.
- After you resume, the cards blocked by the sign-in problem are put back in the queue by themselves.
- A sign-in failure on one route does not pause the loop when a working fallback route is set.

## Retrying cards

- `retry` now finds every card that the Foreman status lists as blocked.
- When an issue is held, `retry` says how to release it, or releases and retries it.
- When an issue has no card, `retry` says what to do instead.

## In Claude Code

- A bug fix's tests are checked whatever their file naming, and blocked reasons say what was actually run.
- A bug fix whose new test sits inside the same source file, such as a Rust test module or a Python doctest, is checked the same way.
- The Foreman's replies about problems in Conveyor itself are kept and reach you, and are noted in a file in the project's Foreman folder.
- Cards are told to put many similar actions into one script run once, to keep their working context small.
- Cards no longer start tests they cannot take a list of files for; a full test run is used for those projects.
- Each project gets a test map, built at setup and kept current, so a card runs only the tests that cover its change.
- A card whose tests fail for missing dependencies says so, instead of reporting test failures.
- A test run that takes a long time while still making progress is no longer flagged as stuck.

## Reliability

- A record the engine cannot read is set aside in a quarantine file and named on the Board, instead of stopping the loop.
- The engine's own checks now catch records written in a format they do not accept, before they reach the loop.
- Full test runs now record per-file times, as touched-test runs already do.
