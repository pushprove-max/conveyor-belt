# 1.6.0

This release makes the way Conveyor lands and releases changes more flexible, and makes the Board, /units and the benchmarks easier to read and act on.

## Landing and releases

- Cards can now land into one open pull request that collects them until you merge it, instead of one pull request per card or straight to the default branch.
- A new "Land as" rule chooses between landing on main (the default) and landing into that shared pull request.
- A new "Merge PR" rule decides who merges the landing pull request: you with the Board's Merge button, the release, or Conveyor once the belt is empty and its tests passed.
- The Board's Merge button shows while a pull request is open, with its card count and a link to it.
- A pull request that GitHub refuses to merge stays open, and the reason is shown on the Board and to the Foreman.
- A ready card no longer waits behind another card that changes the same files and is still being built. It lands first, and the other card is fitted onto the new main afterwards.
- A card that changes a few lines in a test file now runs only the test cases it touched, not the whole file.
- A card never runs the whole test suite. It runs each test file on its list alone, in its own process with its own time limit. Conveyor has built-in one-file runners for Node, pytest, Go, Rust, Gradle, Maven, .NET, Swift, PHP, Elixir, CTest and Dart, and uses the pack's one-file command when it is set. The rule "Whole suite in a card" is removed.
- A card that is blocked because its tests failed again now says which file failed and shows the failing lines.
- When Split large issues is On and a card's change has grown past the file limit (`split.growFiles` in the pack), the judge decides whether to split it. When it splits the change, the core change stays on the card and the rest becomes follow-up issues.
- A card that was blocked for no reason now shows the builder's last message and where its logs are kept.
- A card whose tests were running is no longer stopped or retried when Conveyor takes a new version. It moves to the new code at its next step.

## The Board

- Onboarding: a first-run setup dialog walks you through the project rules, step by step, and reopens until the repository is set up. It does not ask for the Merge PR rule. On each step, Next sets the default for each rule that you did not set.
- Needs you shows the reason for each blocked card straight away, with the next step and its buttons beside it.
- A declined finding is laid out as a level badge, a file link, a bold claim and its proof, with code shown in its own style.
- Declined has a "Dismiss all" button that clears every open line, not only the ones on screen.
- Parts of one large piece of work show as one row, with how many parts are done.
- A card's Done-when check opens to each item, with its evidence and who gave it.
- The Board shows Live or Polling beside the feed status, and the number of cards stopped for you in the tab title.
- You can choose 12-hour or 24-hour time, and month-first or day-first dates, in Customize.
- Queue groups waiting cards and cards awaiting deploy, with each group collapsible.
- The Board no longer reloads while you are typing a Needs-you answer. It shows a "New version. Reload" notice instead.
- Your list lengths, drafts and filter are kept through a reload.
- A hidden tab stops refreshing, and its panels redraw only what changed.
- Settings for each card's builder, reviewer and judge (model and effort) can be changed on the Board, with a Pick for me button that suggests settings.
- Queue, Board and Needs you show the settings and what each waiting card depends on more clearly. Menus stay inside their cards.
- The Tests page search also finds test case names.
- Benchmarks has its own tab with history, a page per run, comparisons, a cost estimate before you start, and an infographic. Each action shows its result beside it.
- Benchmark arms can be checked by clicking their box.
- The Release panel shows the Release button, disabled, with what it waits for.

## In Claude Code (/units)

- The /units pane shows a build matrix: each card's steps, its age and its cost, with the title after the cost.
- The pane has a count band (on belt, ready, waiting, needs you) and a pick order that names what each waiting issue waits for.
- Worker activity shows a progress bar of tests done of all while a card is testing.
- The band and status line are removed. Only the pane remains, and toasts still show when it is on.
- Times in /units follow the Board's 12-hour or 24-hour setting.
- The snapshot warning no longer appears while the live feed is connected.
- "Waiting for" entries say why the issue it waits for is not moving.

## Setup and the Foreman

- Setup turns on the one-hour prompt cache for the Foreman. A session that you claim as the Foreman keeps the cache time it started with. Restart it to get the one-hour cache.
- A new standing rule, review-retry, lets the watcher retry a card blocked by its review without waking the Foreman.
- The Foreman hears of GitHub, sign-in or reachability trouble only when it lasts three checks in a row, so a short outage wakes nobody.
- In the plugin's own repository, the Foreman files plugin problems there as issues and lists unfiled ones at start-up. In other projects, the Foreman tells you about a plugin problem, and you file it in the plugin's repository.
- Issues opened by people outside the project are held until you release them.
- Issues filed in one command are all held, and a release given just after filing is kept.
- Issues the Foreman files for a parent issue stay grouped under it.
- A review follow-up that cannot be filed for privacy reasons is masked and filed rather than blocking the card.
