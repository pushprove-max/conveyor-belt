# 1.8.0

This release makes the Board and the engine more reliable for stuck, stopped and held cards, and fixes Benchmarks so new versions show up and run correctly.

## Cards

- A card you stop with `shut` ends its work and is closed as stopped by you. You can start it again with `retry` on its issue, or with `retry` on its card ID for a main-red fix card. A card for a branch with no issue cannot be started again with `retry`.
- `shut` now tells you what it did, or why it did nothing.
- `retry` on a card whose builder has died or stopped restarts it instead of refusing.
- `retry` on a held issue releases the hold when the retry succeeds, so the loop can pick the issue again. If the release fails, `retry` tells you how to release it.
- A builder killed by the system (out of memory or a stop) is reported as killed, not as a proxy failure.
- A stopped engine is named as stopped, with the command to resume it, instead of being reported only as stuck.
- A review that says NO-GO without a numbered finding now stops the card and shows the reviewer's verdict.
- The idle message no longer appears while a card is building.
- Commits work on older git versions (before 2.36), such as Ubuntu 22.04.
- Pick settings: for each seat you choose the models the judge may pick, each with its own lowest and highest effort, and the judge keeps within them.
- Pick settings: when Pick settings is Shadow or On, a retry or restart asks the judge again instead of reusing the last answer.
- Pick settings: a bad or empty answer from the judge is recorded as a failed pick and no longer changes the builder.
- Pick settings: the judge's pick no longer replaces your builder on comparison cards or blocked retries.
- Pick settings: the judge's pick is priced on the card.
- Each card's page shows the judge's pick of seats and the judge's reason for each. In Shadow, the card builds on the project's seats, and the page shows the pick that the judge proposed.

- A card whose review says NO-GO goes back to its fix session until a review says GO or it has used all its reviews. The loop also ends early: after the one review that follows a rebase, a test fix or a lint fix, or when a P2 or P3 finding comes back after its fix and that review has no P0 or P1 finding. A P0 or P1 finding that comes back after its fix blocks the card, even when it has reviews left. When the loop ends and the card lands after a NO-GO, the findings that are still open are filed as follow-ups. A card whose issue is a follow-up two levels deep files no follow-ups: its open findings go to the Declined list, and the reason names the depth cap. A privacy finding in the card's own change gets one more fix round and one more review. The cards guide tells more under "When the fix loop ends". Before, a card could count the reviews of other cards with the same issue number, even from another project, so it stopped after one review and filed its findings, a P0 among them, as new cards. Each card now records why its fix loop ended, and the Board shows it.

## The Board

- Benchmarks lists new Conveyor versions without waiting for a benchmark run. With the default source, a version shows when its tag is in your local checkout. With a source that is read over the network, the list is read again when the hour changes. A source given as a `file://` folder is read from its git folder each time.
- Benchmarks: you can archive runs to hide them, or delete them, one at a time or several at once from History. You can restore or delete an archived run from its own row in the Archived view.
- Benchmarks: a run that is running cannot be archived or deleted; stop it first.
- Overview shows a Plugin problems pane listing noted problems, with Dismiss and File on GitHub.
- File on GitHub opens a preview you can edit. When you click File the issue, the Board checks the edited text for private details before it files the issue.
- The Tests page lists the test files your project's settings name, not only `*.test.*` files, and shows saved times on each file.
- Rules: a "Done without asking" setting you switch On stays On instead of flipping back to Off.
- Rules: the Pick settings On line now describes trial builds on the challenger, not the Shadow behaviour.
- Rules: a model price you save stays saved instead of flipping back.
- Rules: on narrow windows the Rules panel takes the full width and its labels and controls stack, so text is readable.

## In Claude Code

- `/units` shows changes to the belt within seconds, not on the next minute.

## Setup and tests

- Setup proposes test file patterns from your project's test settings, and doctor warns when a test command runs files those patterns miss.
- Test files in projects with custom patterns (such as `test-*.mjs`) are traced correctly when they fail or are flaky.
- Tests with node:test, Jest, Vitest, pytest and Go are counted as individual cases. A JavaScript case whose name is a template string with `${...}` is not counted.

## Benchmarks

- Conveyor arms run with a newer jq and a newer git inside the task container, and report a clear reason if a version cannot run there.
- Conveyor arms' reviews can run commands in the task container, so reviews no longer stall on the sandbox.
- Conveyor arms' test step runs Django test files through Django's own runner.
- Conveyor arms leave Python cache files out of their changes.
- A trial whose card is waiting for main to change ends at once and is graded on its patch, instead of running until the time limit.
- Fixed a bug where a Conveyor arm could test an older copy of a project and reject a correct fix.
- Versions released before these fixes get the same container support, so comparisons are fair.

## Releases

- When main moves after the release suite has passed, the release reruns only the tests that the new changes touch, not the whole suite. When the changes touch the pack's `test` settings or a file that its suite commands name, the whole suite runs.
