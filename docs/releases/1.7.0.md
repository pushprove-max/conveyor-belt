# 1.7.0

This release makes model choice, release checks and the Board's Rules and Tests pages clearer, and makes the engine more reliable when a CLI or a release run goes wrong.

## Cards

- A card that gets a fix no longer loses the test it was waiting on.
- A card blocked by a missing tool now waits and resumes on its own once the tool is back.
- Cards whose work is split into parts now start held when the original was held, and released when it was released, so approved work no longer stalls the queue.
- Card runs finish a little faster.
- A card that starts from an earlier card's kept work is told so, and a card with no kept work never starts on leftover changes.
- A follow-up that changes no behaviour, such as a comment fix or a redundant check, is filed as a cleanup and is no longer blocked for having no failing test.
- A Done-when line tagged as uncertain or likely is now read, so such a card is no longer blocked by mistake.
- On macOS, a card's test runs work when your shell is zsh. Before, they stopped with a 'command not found' error.
- With pushing off, a split issue closes once its parts have landed, and landed issues show as landed, not pushed, instead of as open work.
- The Foreman is woken again for a card that stays blocked with no question to you about it.
- The Foreman stops its idle keepalive pings after a ping that did not keep the model's cache warm, so you pay for one such ping, not a run of them.

## The Board

- The Rules page is reorganised into six groups with a search box. Each rule has a plain label and a short explanation, and the pinned issues show their titles.
- The Release panel shows the fix cards of a red release run, their states, and when the suite runs again.
- The Release panel asks whether the suite should run its test files one by one or in parallel before it starts.
- The Tests page has a "Split it" action for test files that should be divided, and flags test files that run other tests or wait on real processes.
- The Tests page's "Explain the slowdown" reads the commits that changed a slow test, not only the card that ran it, and shows times in your time zone.
- The Tests page's "Rewrite as a direct check" button opens an issue preview that asks to rewrite a test that relies on a proxy as direct checks of its behaviour. You can edit the preview before you file it.
- The cache-write alert names the card steps that wrote the most cache.
- The Board now has prices for the newer Codex models. Their costs previously showed as unknown.
- In Shadow mode, the Pick settings rule records the model it would pick for each card, while the card builds on its current builder. The Board shows, by group and builder, how many cards it picked, the cost of all their steps per landed card, and the share of its landed cards that needed no retry. Set the rule to On to run trials of a challenger model.

## In Claude Code

- `/units` shows the true number of cards landed today, not just the most recent twenty.
- `/units` keeps showing your weekly usage limit even when the Board's data file grows large.

## Releases

- A release that fails on some tests records its fix cards and starts again by itself once they have all landed. The Foreman is told when that happens or when a fix is closed without landing.
- Release test runs can judge each failing test on its own before deciding whether it blocks the release, so flaky tests no longer stop a release.
- Release suites can run their test files in parallel, and the longest files start first.
- Before a release, when the plugin's files have changed, Conveyor validates the plugin on the oldest Claude Code version it supports.
- A release that passes no longer shows a stray system warning as its reason.
- The release notes draft is checked against the notes style as it is written, and lines that break it are rewritten.

## Setup

- Model choice respects both the pack's list of allowed models and the models your CLI reports, and doctor warns when the two differ.
- When `codexProxy` sends the Codex sessions of both roles through a proxy, the proxy's own list of models is added to the menu. A route of kind `api` adds no models.
- Doctor catches a Claude seat that returns an empty answer, and the error names the seat.

## Filing and Issues

- Issues the Foreman files are held from the start, even when the filing command's output does not link them.
- Issues filed for a repository whose name differs from its local record are now found and held correctly.
