# 1.2.0

This release makes setup install what Conveyor needs and start the Board, keeps every issue held until you release it, and adds Hold and Fix actions for blocked cards.

## Setup

- Setup checks each required tool against its minimum version and installs any that are missing or too old, including jq 1.8 or newer and Claude Code 2.1.322 or newer.
- Setup uses Homebrew on macOS and your system package manager on Linux, and asks through Claude Code's prompt before it needs administrator rights.
- Setup starts a ready-to-use Board on this machine without asking for an admin password. You can set a password later on the Board's account page if you want to log in from another device.
- Setup starts the required logins for GitHub, Claude and Codex when they are missing.
- Setup looks for a local Claude API proxy and asks whether to use it as a fallback for your subscription login.
- If an install fails, setup stops and names the tool and the reason.
- `doctor` lists any tool below its minimum version, shows the Board's address (or says the Board is not running and how to start it), and names why it cannot read a project when that happens.

## Issues and the queue

- New projects start with new issues held, so a new issue waits for your release.
- Setup holds every issue that is open when you install, so an existing backlog never starts building on its own.
- Running setup again does not change your release choices or the held list.
- To let new issues queue by themselves, set the project's start option to queue.

## The Board

- Each blocked card has a Hold button. Hold takes the card off the belt, keeps its issue held and keeps its work, so a later retry picks up where it left off. Undo is available.
- When Conveyor can fix a block itself, the blocked card shows a Fix button and says in one line what it will do. Blocks with no automatic fix show no Fix button.
- When Conveyor runs on the same machine as the Board, the Board reads everything locally. No separate build machine is needed.
- Overview panels show their data, or an empty state such as "No cards on the belt," instead of an error.
- When a panel cannot read its data, its message names the real cause, and it has its own Restart the Board's feed button right there. The Health panel has the same button.
- Health shows each Claude and Codex route (subscription and proxy) with its state.
- Bulk Optimize shows validation errors next to the button you clicked, not only at the bottom of the page.

## Foreman

- Claiming the Foreman role opens the Board in your browser, once per claim. Repeating the claim, resuming, using `/clear`, or compacting does not open another tab.
- If the Board is not running, the claim prints one line saying so, and the claim still succeeds.
- Turning off the Board auto-open setting also turns off this opening.

## Claude sessions

- If a Claude session's subscription login fails before any work, the step runs again through your API proxy if one is set up. This includes the Claude judge and the other Claude steps.
- The card records which route each step used.
- If both the subscription and the proxy fail, the card's reason names both causes.

## Build failures

- A build, fix or review session that ends without doing any work now says why in the card's reason, such as "the Claude CLI is not logged in."
- The timeout note appears only when a session actually times out.
- A session that fails before any work is retried once after the cause clears, instead of staying blocked with no next step.

## Commands

- Commands run from a project's main checkout find the project from the current folder, so `retry` and `snapshot` work with a marketplace install.
- Commands no longer print "fatal: not a git repository" when run inside a project.

## Claude Code

- With the side pane set to on, the Conveyor pane opens at the start of each session.
- If the pane cannot be placed, you get one line saying why and that `/units pane on` will try again.
