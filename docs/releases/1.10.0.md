# 1.10.0

This release lets a release's full test suite run on a Namespace Devbox or a Linux machine over ssh, quiets the Foreman's wake-ups, and fixes several Board and status problems.

## Releases

- You can choose where a release's full test suite runs: this machine (the default), a Namespace Devbox leased for the run, or any Linux machine you reach over ssh.
- After the run, Conveyor keeps the Namespace Devbox, and the box stops itself after 15 minutes idle. The "After a run" row in Capacity shows this.
- A remote suite run does not use up the build machine's test slots, and files run at once on a remote box are capped at that box's slots.
- A remote run that cannot start ends as "not started" with its reason, and it never moves to another machine.
- The Release panel shows the remote machine's steps as they go: Start, Set up, Check out, Run, Bring back results and Give back the box.
- Stopping a release run also stops a remote run and gives the box back.
- A run that did not start offers "Run on this machine instead" and "Run suite again", and it names the fix, such as logging in to Namespace.
- The Release panel asks "On which machine?" and presets the answer to your rule's choice. Your answer applies to that run only.
- A Linux machine that lacks a tool the suite needs ends the run as "not started" and names the tool.

## Rules

- A "Release suite runs on" row in Capacity lets you pick the release suite's machine, with a Check button that lists each required tool as ok or missing.
- When a tool is missing, Check shows it as missing with a "Set up now" button. The button is off in this release.
- A Namespace Devbox that is not logged in shows the `devbox login` command to run in a terminal, and Check stays off until you log in.
- Check the box turns on as soon as you log in to Namespace, with no page reload.
- The Box row shows when the devbox was set up.
- The "Use this machine" button switches the release suite back to this machine.
- The "Test files at once" note shows the suite machine's slot count.

## Setup

- Setup offers to write a script that prepares a bare Linux machine for the release suite, and it tells you the project must finish that script.

## The Board

- A card that has been pushed and whose issue is closed leaves "pushing" at the next refresh.
- While a push runs, the Board shows which cards it carries and how long it has run.
- Conveyor no longer marks main red for a test file that passes under the project's own test command.
- A main-fix card with no change clears the red mark when that test passes, instead of blocking with "still fails on main".
- A full test run that died with no result no longer shows as the latest full test error.
- Once a stale full test error is cleared, it no longer appears in the status or as the Board's last result.

## The Benchmarks tab

- The scoreboard's Lint clean note says "No new pyflakes finding (ruff, rules F) in the Python files the patch changes."
- When all arms made the same change, the scoreboard's patch note says, for example, "All three made the same one-line fix".
- Where a cost or machine time is not known, the scoreboard shows "not kept" in place of the explanatory sentences.
- The number of tasks that would show a difference is capped at the size of the task set.
- The Versions verdict starts with "No regression." unless the newest version resolves fewer tasks by more than the noise. It no longer says "Better." or "A regression.", and a version with no changes kept shows "not kept" in place of "none".
- The live run no longer shows a sentence about the usage guard.
- In the last run, each arm's result is "resolved" or "unresolved", or "not kept" when the result was not graded.
- The task view shows "fail-to-pass · pass-to-pass" in lowercase.
- "Run this task again" shows no answer line, and when it cannot run, the page says why.
- In Plan a run, when the usage guard is off, the Usage guard row shows "fits in the week left" when the week left is known, in place of "off; the guard will not stop the run".
- Plan a run lists every arm, including those not offered.
- Start stays off while a ticked arm is not ready, and the page says why.

## /units

- A remote suite line names the machine after the commit, and shows its progress while starting, setting up, checking out or bringing back results.
- A running remote suite shows its time, cases done and failures.
- A finished remote suite shows its result, time, when it ended and whether the box was given back.
- PICK ORDER lists the next five issues the engine will pick, in order, with their priorities.
- When more issues are ready than it lists, PICK ORDER shows the number ready, for example "next 5 of 7".
- An issue the machine is holding back shows the reason under its row.
- PICK ORDER says the queue is empty when nothing is ready and nothing is waiting.
- /units no longer goes blank when the Board's live data is large.

## The Foreman

- When several awaited issues land, the Foreman gets one wake that names each landing and its commit, not one wake per landing.
- A follow-up, a blocked or stuck card, and the idle wake still reach the Foreman at once.
- Restarting the waiter sends any held landing right away.
- The Foreman's release question asks which machine to run the suite on, with your rule's choice marked Recommended.
- The Foreman's stop check no longer looks for questions in its replies.
- Before the Foreman files a fix, the issue must name the cause of the problem, not only its symptom.
- A Foreman turned on in a session that is already running gets the project's rules.
- The Foreman asks you questions only through a picker, and it answers a question without filing or fixing anything unless you order it.
- Before it asks you something, the Foreman checks your earlier rulings for the same topic.
- Pickers offer real options, mark the Foreman's own choice Recommended, and tag unchecked points as likely.
- When you have not answered for 30 minutes, the Foreman holds its new questions and asks them together later.
- An approved mockup is the spec: the Foreman compares live output with it and lists every difference before it calls work done.
- Stopping a card is a separate step from closing its issue.
- A card blocked at the follow-up depth limit goes to you with the reason.
- The Foreman never retries a refused action in another form.
- The Foreman never asks you to do manual work. A step that needs your hands, such as a login, is given as one command.
